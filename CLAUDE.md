# Project rules

## Branching
- When starting a story (GitHub issue on the NINA MCP Benchmarking project), if it will involve code changes of any kind, check out a new branch for that story before making changes.
- Name the branch `<issue-number>-<short-slug>`, e.g. `4-harness-tier1`.
- Branch from an up-to-date `main`.
- Stories with no code changes (e.g. setup done by hand on the mini PC) don't need a branch.
